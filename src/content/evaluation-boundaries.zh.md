只有明确评估对象、分母和执行流程，一个数字才具有解释价值。这篇笔记梳理阅读本作品集中项目时需要区分的概念，不报告新的实验发现。

## 数据就绪是前置条件

Sentry / AppWorld 项目中的 **147/147** 指数据任务完整性检查：参与检查的 147 个任务均通过了数据验证。它不代表智能体执行或解决了这些任务。

报告智能体成功率，需要有实际评估的智能体运行、明确的成功判定标准，以及满足该标准的任务数量。单独的数据完整性检查不能提供这些任务完成结果。

| 检查           | 能够支持的结论                 |
| -------------- | ------------------------------ |
| 数据任务完整性 | 任务数据是否通过完整性检查     |
| API 适配       | 模型接口是否与运行环境兼容     |
| 智能体评估     | 智能体运行是否满足任务成功标准 |

## 验证集和测试集回答不同问题

CIFAR-10 项目已报告的最佳 CNN 结果为：**验证集准确率 72.08%**、**测试集准确率 71.34%**。每次呈现这些数字时，都应同时保留对应标签。

验证集结果可以辅助模型选择。测试集结果则应结合固定的评估流程解释。互换标签、只展示较大的数字，或把两个数字都称为测试性能，会模糊实际测量的内容。

目前提供的摘要不包含数据划分细节、多次运行方差或各项消融数值。在获得实验记录之前，这些信息应保持未报告状态。

## 一份简短的报告清单

- 写明测量对象：数据、接口、候选公式，还是智能体运行。
- 说明分母和评估判定标准。
- 明确标注验证集与测试集。
- 区分已完成检查和仍在进行的实验。
- 将缺失证据作为局限说明，不用假设补齐。

边界清楚的结论，更便于他人检查，也更适合作为后续研究的起点。
