消融实验的价值，在于让读者能够辨认：改变了什么、哪些条件保持一致，以及结论由哪项测量支持。这篇方法笔记说明如何记录和解释 CNN 实验，不报告额外实验或新的性能结果。

## 从已有证据开始

CIFAR-10 项目使用 PyTorch，涉及 CNN 与 MLP、Adam 与 SGD、BatchNorm 和 Dropout，已完成多种消融实验。已报告的最佳 CNN 结果为：**验证集准确率 72.08%**、**测试集准确率 71.34%**。

目前提供的摘要不包含各项消融得分、训练轮数、多随机种子结果或置信区间。因此，仅凭这两个总体指标，不能判断某个组件单独带来了多少提升。尚未报告的比较应保持未报告状态，不能将推测的提升填入结果表格。

## 让每组比较可以检查

### 明确改变的因素

解释结果前，先为参考配置命名，并说明本次比较计划改变什么。CNN 与 MLP 的比较改变了模型类别，不能将其描述为只隔离了某一层卷积的作用。比较优化器时，也需要分别写清超参数设置：数值相同的学习率，并不必然对应可比的训练过程。

下面是一份记录方案，**不是已测量的实验结果表**。

| 因素      | 对照思路                                | 需要记录的证据                                 |
| --------- | --------------------------------------- | ---------------------------------------------- |
| 模型结构  | 在明确的数据与训练协议下比较 CNN 和 MLP | 层结构、参数量、预处理、训练预算               |
| 优化器    | 比较 Adam 和 SGD，并明确各自设置        | 学习率、调度策略、优化器选项、损失与准确率日志 |
| BatchNorm | 比较参考网络与明确指定的 BatchNorm 变体 | 层的位置、其他配置变化、训练与评估模式         |
| Dropout   | 比较参考网络与明确指定的 Dropout 变体   | 插入位置、丢弃概率、训练与评估模式、检查点标识 |

### 将配置与测量放在一起

为每次运行同时记录数据划分、预处理、代码版本、训练配置和检查点选择规则。条件允许时，保留训练集与验证集曲线。单个最终准确率无法说明训练是否中断，也无法解释不同运行是否使用了不同的检查点选择方式；日志能为这些问题提供检查依据。

以下 **JSON 仅为空白记录模板**，不对应已经执行的某次运行。未知值统一为 `null`；准确率字段应事先说明单位，并保持一致。

```json
{
  "record_type": "template",
  "model": null,
  "optimizer": null,
  "batch_norm": null,
  "dropout_probability": null,
  "seed": null,
  "epochs": null,
  "split_id": null,
  "validation_accuracy": null,
  "test_accuracy": null,
  "checkpoint_path": null,
  "log_path": null
}
```

## 保留验证集与测试集的边界

验证集测量可以用于配置与检查点选择。留出的测试集应评估已经选定的流程，而不应反复用于指导修改。展示结果时，应分别标注验证集 **72.08%** 与测试集 **71.34%**，不能将两者当成可互换的测试性能估计。数据划分标识和选择规则能够帮助核查这条边界；当前摘要尚未提供这些信息。

## 补充下一层证据

下一步最有价值的材料，是原始逐次运行配置和指标记录，再据此整理仅包含可查证观测值的对照表。对无法构成受控比较的差异，也应明确说明。以后可以通过记录随机种子的重复运行分析波动，并在清楚说明计算流程的前提下提供不确定性估计。这篇笔记不声称已经完成多随机种子评估或计算置信区间。在获得相应证据之前，已报告的最佳结果支持的是边界明确的项目概述，而不是某个组件带来提升的因果结论。
